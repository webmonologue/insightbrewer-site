### Dots·피클·Muse·Claude Duet·Gemini Task·Grok Bot과 OpenClaw·Hermes 비교

AI 비서에 관한 제품 소개를 보면 비슷한 장면이 등장합니다. 메일을 읽고 일정을 정리하며, 필요한 정보를 찾아 작업을 이어갑니다. 사용자가 대화창을 닫은 뒤에도 일을 계속한다는 설명도 이제 낯설지 않습니다.

OpenAI의 Dots, 피클(Pickle), Meta의 Muse는 이런 상시형 비서의 모습을 보여줍니다.[1][2][11] Anthropic의 Claude Duet, Google의 Gemini Task, xAI의 Grok Bot 역시 지속적인 업무와 반복 작업을 다룹니다.[12][13][14] 한편 OpenClaw와 Hermes Agent는 사용자가 실행 환경과 모델, 도구를 구성해 비서를 운영하는 방식을 제공합니다.[5][8]

겉으로는 모두 대화로 일을 맡기는 AI이지만, 사용하는 방식과 운영 책임은 같지 않습니다. 서비스가 마련한 클라우드 컴퓨터에 계정을 연결하는 경우도 있고, 자신의 컴퓨터나 서버에서 에이전트를 실행하는 경우도 있습니다.

이 차이를 이해하면 어떤 제품이 자신에게 맞는지뿐 아니라, 보안에서 무엇을 확인해야 하는지도 조금 더 분명해집니다.

*이 글은 공식 제품 안내와 공개 보안 문서를 바탕으로 한 비교입니다. 직접 사용한 성능 평가나 보안 순위는 아닙니다. Google의 Gemini Spark는 공식 도움말에서 Task로 이름이 변경된 것을 확인해 ‘Gemini Task(구 Spark)’로 표기했습니다. Google Tasks 서비스와는 구분됩니다.*[13]

## 먼저, 완성된 서비스를 쓰는 것과 직접 운영하는 것을 나눠 봐야 합니다

Dots부터 Grok Bot까지는 서비스 제공자가 운영하는 에이전트 환경에 사용자의 계정과 업무를 연결하는 방식이 중심입니다. 사용자는 앱에서 작업을 맡기고 접근 권한을 설정합니다.[1][12][14]

OpenClaw와 Hermes Agent는 직접 운영할 수 있는 오픈소스입니다. 자신의 컴퓨터나 서버에서 실행하고, 사용할 모델과 연결할 도구를 선택하는 방식에 가깝습니다. Hermes는 별도의 원격·격리 실행 환경도 지원합니다.[5][8]

이 구분은 어느 쪽이 더 우수하다는 의미가 아닙니다. 관리형 서비스는 준비된 기능을 사용하는 편의가 있고, 직접 운영하는 방식은 환경을 조정할 여지가 큽니다. 대신 설치와 업데이트, 접근 통제, 기록 관리 등 운영자가 판단할 일도 늘어납니다.

## 주요 AI 비서는 무엇에 초점을 두고 있을까

### Dots: 여러 도구에 걸친 업무를 계속 이어가는 방식

Dots는 대화 사이에도 진행 중인 업무를 추적하는 에이전트를 지향합니다. 자체 클라우드 컴퓨터와 브라우저를 사용하고, 연결된 앱과 이전 대화의 맥락을 활용합니다. ChatGPT·Slack·Teams에서 대화하며, 필요한 작업을 Work나 Codex에 나눠 맡길 수도 있습니다.[1]

비교할 때 눈여겨볼 부분은 하나의 요청을 처리하는 능력뿐 아니라, 여러 작업의 진행 상태를 유지하는 방식입니다. 다만 메시지를 주고받는 채널, 업무 앱 연결, 사용자의 로컬 컴퓨터 연결은 서로 다른 권한입니다. Slack에서 대화한다고 다른 앱과 컴퓨터까지 자동으로 연결되는 것은 아닙니다.[1]

### 피클: 개인의 기억과 생활 속 행동을 연결하는 방식

피클은 사용자를 오래 이해하는 개인 AI를 강조합니다. 예약 메일에서 정보를 찾고, 약속 시간을 조율하며, 계정과 브라우저를 이용해 작업하는 흐름을 설명합니다. 다른 사람이나 다른 피클과 대화할 때 공유할 정보도 별도로 설정합니다.[2]

이런 구조에서는 무엇을 기억하는지와 무엇을 전달해도 되는지를 나눠 봐야 합니다. 사용자의 일정을 알고 있다는 사실이 그 일정의 내용을 다른 사람에게 설명해도 된다는 뜻은 아닙니다. 피클의 공개 보안 설명도 계정 접근, 저장된 기억, 타인과의 공유를 구분해 다룹니다.[2]

### Meta Muse: 생활형 작업과 별도의 외부 통신 검토

Meta는 Muse를 사용자별 클라우드 컴퓨터인 Muse Secure VM에서 작동하는 개인 에이전트로 소개합니다. Muse 앱과 WhatsApp에서 대화하고, 브라우저를 이용해 양식 입력이나 예약 같은 작업을 수행합니다. 대화에서 배운 내용을 기억해 제안하는 기능도 설명합니다.[11]

보안 설계에서 눈에 띄는 것은 별도로 분리된 Sentinel 에이전트입니다. Meta는 Muse의 외부 통신이 Sentinel의 승인을 거치며, 메일 발송과 구매 같은 민감한 행동에는 사용자 확인을 받는다고 설명합니다.[11]

다만 별도 검토 에이전트가 있다는 사실이 모든 잘못된 행동을 막는다는 뜻은 아닙니다. 또한 발표문에서 향후 기능으로 소개한 Confidential VM을 현재의 Secure VM과 같은 것으로 이해해서는 안 됩니다.[11]

### Claude Duet: 연결된 업무를 살펴보고 필요한 일을 먼저 알리는 방식

Claude Duet는 자체 브라우저가 있는 클라우드 컴퓨터에서 작동합니다. 연결된 메일과 일정, 업무 도구를 확인해 아침 브리핑을 제공하고, 진행 상황이나 후속 대응이 필요한 내용을 알려주는 방식입니다. 기존 Claude의 기억·스킬·커넥터도 활용합니다.[12]

이때 연결 계정을 확인하는 것은 실시간 감시가 아니라 몇 시간 간격의 점검으로 안내됩니다. 메시지 전송·결제·서명·삭제 전에는 승인받도록 설계됐으며, 증권 거래나 계좌 간 자금 이동처럼 승인을 받더라도 허용하지 않는 작업도 있습니다.[12]

업무 중심 기능을 제공한다는 사실과 조직용 관리 체계가 제공된다는 사실도 구분해야 합니다. 공식 문서는 연구 프리뷰의 대상 플랜과 지역, 대기명단 조건을 별도로 안내하며 Team·Enterprise 미지원을 명시합니다.[12]

### Gemini Task(구 Spark): Google 앱과 반복 작업을 연결하는 방식

Google이 Spark로 소개했던 기능은 현재 공식 도움말에서 Task라는 이름으로 안내됩니다. Gmail·Calendar·Drive 등 연결된 앱과 개인화 맥락을 활용하고, 여러 단계의 작업과 예약된 실행을 지원합니다.[13]

실행 방식은 로컬 Chrome과 클라우드 원격 브라우저로 나뉩니다. 로컬 작업에는 기기와 브라우저가 켜져 있어야 하지만, 원격 작업은 사용자의 기기를 닫아도 이어질 수 있습니다.[13]

Google 앱을 사용하는 사람이라면 연결 범위를 살펴볼 만합니다. 다만 개인 Google 계정에서 Google 업무 도구를 이용하는 것과 회사의 Workspace 계정에서 조직 정책에 따라 사용하는 것은 다릅니다. 공식 도움말은 개인 계정 조건과 직장·학교 계정 제한을 명시하고 있습니다.[13]

### Grok Bot: 여러 Bot이 작업을 나누는 방식

Grok Bot은 브라우저·파일시스템·터미널이 있는 지속형 클라우드 컴퓨터를 이용합니다. 여러 Bot에 역할을 나눠주고 연결된 서비스나 브라우저에서 작업을 수행하는 구조입니다.[14]

여기서는 여러 Bot이 같은 계정의 클라우드 컴퓨터를 공유한다는 점을 주의해서 봐야 합니다. xAI 보안 문서는 Bot을 나누는 것을 보안 경계로 사용하지 말라고 명시합니다. Bot의 이름과 역할이 달라도 파일과 브라우저 세션, 일부 자격증명은 공유될 수 있습니다.[15]

행동 검토에는 모델 기반 Auto Review와 승인 규칙을 사용합니다. 따라서 모든 외부 행동을 사람이 하나씩 승인하는 방식이라고 단정하기보다, 어떤 행동이 자동 허용되고 어떤 경우에 확인을 받는지 실제 설정을 살펴봐야 합니다.[15]

### OpenClaw: 메시징과 실행 환경을 직접 연결하는 방식

OpenClaw는 사용자의 컴퓨터나 서버에서 Gateway를 실행하고, Discord·Telegram·WhatsApp 같은 메시징 채널을 에이전트와 연결하는 오픈소스입니다. Gateway가 연결과 세션을 관리하고, 별도로 연결한 장치가 실행 기능을 제공할 수 있습니다.[5][6]

기존 메신저를 개인 비서의 입구로 활용하면서 모델과 도구를 구성하려는 경우에 검토할 수 있습니다. 다만 공개된 신뢰 모델은 하나의 Gateway를 한 운영자 또는 서로 신뢰하는 팀이 사용하는 것을 전제로 합니다. 서로 신뢰하지 않는 사용자를 같은 에이전트에 연결하고 대화방만 나누는 것으로 강한 격리가 이뤄지지는 않습니다.[7]

따라서 누가 메시지를 보낼 수 있는지와 그 메시지가 어떤 실행 권한을 사용할 수 있는지를 함께 관리해야 합니다.

### Hermes Agent: 기억과 재사용 가능한 작업 절차를 축적하는 방식

Nous Research의 Hermes Agent도 직접 운영할 수 있는 오픈소스 에이전트입니다. 터미널·데스크톱·메신저에서 사용하고, 여러 모델 제공자와 도구를 연결하며, 예약 작업이나 병렬 작업을 구성할 수 있습니다.[8]

특징 중 하나는 지속적인 기억과 스킬입니다. 사용자의 맥락을 기억하는 것과 별도로, 작업에서 얻은 절차를 스킬 문서로 저장해 다음 작업에서 불러오고 수정하는 방식을 지원합니다. 여기서 ‘학습’은 기본 모델의 가중치를 자동으로 재학습한다는 뜻이 아니라, 지침과 절차를 저장하고 재사용한다는 의미로 구분하는 편이 정확합니다.[8][10]

보안 문서는 사용자 허용 목록, 위험 명령 승인, 파일 쓰기 제한, 격리 실행 등의 통제를 설명합니다. 다만 이런 기능이 있다는 사실과 현재 설치에서 원하는 수준으로 활성화됐다는 사실은 다릅니다. 실제 실행 환경과 설정을 확인해야 합니다.[9]

## 비교 기준은 기능 개수보다 맡기려는 업무에 가깝습니다

공식 설명을 기준으로 활용 방향을 정리하면 다음과 같습니다. 실제 성능의 우열을 뜻하는 것은 아닙니다.

- **Dots:** 여러 도구와 프로젝트의 진행 상태를 유지하며 후속 작업을 이어가는 방식.[1]
- **피클:** 개인의 기억을 생활 속 작업과 사람 간 조율에 활용하는 방식.[2]
- **Muse:** 생활형 작업을 수행하면서 별도 에이전트가 외부 통신을 검토하는 방식.[11]
- **Claude Duet:** 연결된 업무를 주기적으로 살펴보고 브리핑과 후속 대응을 제공하는 방식.[12]
- **Gemini Task:** Google 앱의 맥락을 활용해 여러 단계의 작업과 반복 실행을 연결하는 방식.[13]
- **Grok Bot:** 여러 Bot이 공유 실행 환경에서 역할을 나눠 작업하는 방식.[14][15]
- **OpenClaw:** 메시징 채널과 장치·도구를 자신의 Gateway에서 연결하는 방식.[5][6]
- **Hermes Agent:** 모델과 실행 환경을 선택하고 기억·스킬·자동화를 축적하는 방식.[8][10]

선택할 때는 자신이 이미 사용하는 앱과 연결되는지, 필요한 행동을 실제로 수행할 수 있는지부터 확인하는 편이 좋습니다. 이후 승인 방식과 기록, 중단·복구 수단을 살펴볼 수 있습니다. 개인용으로 시작하기 편한 제품이 회사 자료를 연결하기에도 적합한지는 별도로 판단해야 합니다.

## 작동 구조를 보면 보안 문제도 연결됩니다

세부 구현은 다르지만, 에이전트의 작동은 다음과 같은 개념적인 흐름으로 설명할 수 있습니다.

**요청 또는 예약된 실행 → 관련 기억·정보 확인 → 다음 작업 선택 → 권한 검토·필요시 승인 → 도구 실행 → 결과 확인 → 후속 작업 또는 보고**

사용자에게 보이는 채팅창은 이 과정의 입구입니다. 실제 작업은 API, 브라우저, 파일 도구, 터미널 등을 통해 이뤄집니다. 모델이 무엇을 할지 판단하더라도, 실제로 가능한 행동의 범위는 연결된 도구와 계정 권한에 영향을 받습니다.[6][8][14]

가령 “이번 주 메일에서 답장이 필요한 내용을 정리해주세요”라는 요청에는 메일을 읽을 권한이 필요합니다. 하지만 곧바로 발송하거나 삭제할 권한까지 필요한 것은 아닙니다. OWASP도 불필요한 기능과 권한, 과도한 자율성이 잘못된 행동의 피해를 키울 수 있다고 설명합니다.[3]

### 외부 자료가 명령으로 바뀌는 위험

메일이나 웹페이지에는 AI의 행동을 바꾸려는 지시가 들어갈 수 있습니다. 읽어야 할 내용을 실행해야 할 명령으로 받아들이게 만드는 프롬프트 인젝션입니다.[4]

예를 들어 메일 본문에 내부 자료를 다른 주소로 전달하라는 내용이 들어 있다고 가정해 보겠습니다. 이를 사용자의 지시로 잘못 받아들였을 때, 발송 기능과 넓은 자료 접근 권한까지 연결돼 있다면 피해 범위가 커집니다. OWASP도 이와 같은 메일 비서 공격 시나리오를 제시합니다.[3]

따라서 모델에게 조심하라고 지시하는 것과 함께, 애초에 필요하지 않은 실행 경로를 제한해야 합니다. 읽기 전용이어도 다른 도구로 읽은 내용을 외부에 전달할 수 있다면 유출 위험은 남습니다.[4]

### 인증정보 보호와 내용 보호는 다릅니다

피클은 계정 토큰을 격리된 Credential Enclave에서 사용하고 모델에는 토큰 대신 조회 결과를 전달한다고 설명합니다. 그러나 그렇게 읽어온 메일과 대화·기억은 서버에서 처리되며, 필요한 부분이 모델 제공업체에 전달될 수 있습니다.[2]

이는 비밀번호를 모델에 보여주지 않는 설계와, 메일 내용이 외부 처리자에게 전달되지 않는 설계가 서로 다르다는 뜻입니다. ‘암호화’라는 표현만으로 모든 데이터가 사용자 기기 안에 머문다고 이해해서는 안 됩니다.

OpenClaw나 Hermes를 직접 설치한 경우도 마찬가지입니다. 실행 프로그램이 자신의 서버에 있어도 외부 모델이나 검색·브라우저 서비스를 연결하면 관련 데이터가 외부로 전달될 수 있습니다. 직접 운영한다는 것은 데이터 흐름을 선택하고 관리할 여지가 있다는 뜻이지, 자동으로 외부 전송이 없어진다는 뜻은 아닙니다.[5][8]

### 역할 분리와 보안 격리는 다릅니다

업무용 Bot과 개인용 Bot을 따로 만드는 것은 정리에 도움이 될 수 있습니다. 하지만 같은 파일이나 브라우저 세션에 접근할 수 있다면 충분한 보안 분리라고 보기 어렵습니다. Grok Bot은 이 점을 문서에 명시하고, OpenClaw도 신뢰 수준이 다른 사용자는 별도 Gateway와 운영체제 사용자·호스트로 나누는 접근을 안내합니다.[7][15]

조직에서 사용할 때는 이름이나 대화방 구분보다 실제 계정·저장소·실행 권한이 어떻게 분리되는지를 확인해야 합니다.

### 중단, 연결 해제, 기억 삭제는 각각 확인해야 합니다

Dots는 주 작업의 일시정지와 위임·예약 작업의 중단을 구분합니다. 피클과 Claude Duet는 앱 연결을 해제해도 과거 대화에서 얻은 기억이 남을 수 있다고 설명합니다.[1][2][12]

앱을 닫는 것, 앞으로 계정에 접근하지 못하게 하는 것, 이미 읽어온 정보를 지우는 것은 다른 작업입니다. 서비스를 선택할 때는 작업 기록을 볼 수 있는지뿐 아니라, 실행 중인 작업과 예약된 작업을 어떻게 멈추고 저장된 정보를 어떻게 삭제하는지도 살펴봐야 합니다.

## AI 비서의 선택은 운영 방식의 선택이기도 합니다

생활 속 일을 간편하게 맡기려는 사람과, 사내 시스템을 연결해 업무를 자동화하려는 사람에게 같은 구성이 적합하지는 않습니다. 관리형 서비스를 선택하면 제공되는 기능과 정책을 검토해야 하고, 직접 운영한다면 실행 환경과 접근 통제를 유지할 책임까지 고려해야 합니다.

처음에는 메일 자동 발송보다 답장 초안 작성, 일정 변경보다 가능한 시간 정리처럼 범위가 좁은 업무부터 검토할 수 있습니다. 결과의 정확성과 권한 통제를 확인하면서 필요한 행동을 추가하는 방식입니다.

AI 비서가 처리할 수 있는 일이 늘어나고 있습니다. 그만큼 제품을 비교할 때도 답변이 자연스러운지만으로는 부족합니다. **어디에서 실행되고, 무엇을 기억하며, 어떤 권한으로 행동하고, 원하지 않을 때 어떻게 멈출 수 있는지**를 함께 살펴봐야 합니다.

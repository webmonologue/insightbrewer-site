# Obsidian 승인 내보내기 계약

## 입력과 승인

- CLI: `npm run export:obsidian -- --note "vault 기준 상대 경로.md" [--write]`. `--note`는 필수이며 허용 폴더 안의 파일 한 개만 선택합니다. glob·일괄 동기화는 없습니다.
- 기본 경로가 다를 때만 `--vault "/다른/vault"`를 추가합니다. `--project "/다른/site"`는 테스트·별도 로컬 작업용이며 그 경로의 `src/content/blog/`, `public/`가 미리 존재해야 합니다. CLI는 네트워크 요청을 하지 않습니다.
- YAML frontmatter: `title`, `slug`, `description`은 비어 있지 않은 문자열, `tags`는 비어 있지 않은 문자열 배열입니다. `pubDate`는 `--write` 시 필수, `updatedDate`는 선택입니다. `draft`는 생략 또는 `false`만 허용합니다.
- 날짜: `YYYY-MM-DD`(UTC 자정) 또는 `2026-09-14T09:00:00+09:00`처럼 시간대가 명시된 ISO 시각. 미래 `pubDate`, 잘못된 날짜는 dry-run에서도 거부합니다.
- slug: NFC 정규화한 유니코드 문자·숫자, 그 사이 단일 `-`만 허용하며 최대 80자입니다. 공백·점·경로 구분자·인코딩된 경로는 허용하지 않습니다. 짧은 한글 또는 소문자 영문 slug를 권장합니다. 출력 frontmatter에도 slug를 기록하여 Astro URL을 유지합니다.
- `--write`에는 `status: approved`와 일치하는 `approvalHash`가 모두 필요합니다. `approvalHash: 소문자64자리해시`는 frontmatter의 최상위 한 줄이어야 하며 따옴표·주석·여러 줄 값은 허용하지 않습니다.
- SHA-256 입력은 파일 전체를 LF로 정규화하고 frontmatter의 `approvalHash` 줄만 제거한 UTF-8 내용입니다. 공백·마지막 줄바꿈·비공개 메모도 승인 대상입니다. 해시는 서명이나 접근 제어가 아니라 **검토한 리비전 확인 장치**입니다.

## 공개 경계와 링크

- 본문은 정확히 한 쌍의 `<!-- publish:start -->`, `<!-- publish:end -->` 사이에서만 가져옵니다. 마커는 독립된 줄에 두세요. 마커 누락·중복·역순·빈 본문은 실패합니다. 구간 양끝 공백은 정리됩니다.
- 출력 메타데이터는 `title`, `slug`, `description`, `tags`, `pubDate`, 선택 `updatedDate`만입니다. 승인 값·내부 속성·원본 절대 경로·마커 밖 본문은 출력하지 않습니다.
- 공개 구간의 `[[위키링크]]`, `![[임베드]]`, `%%주석%%`, Obsidian callout, raw HTML/HTML 주석을 거부합니다. `TODO:`, `FIXME:`, `PRIVATE:`, `INTERNAL:`, `CONFIDENTIAL:`, `비공개:`, `내부용:`, `개인메모:` 등의 주석, private/internal/confidential 태그·대괄호 표기, `필드:: 값`, 체크박스 작업, `^block-id`도 제거해야 합니다. 코드 예시 안에서도 보수적으로 거부할 수 있습니다.
- 일반 `https://`, `http://`, `mailto:` Markdown 링크와 `#본문앵커`는 유지합니다. 외부 링크의 유효성·내용은 가져오거나 검증하지 않습니다.
- 로컬 링크·이미지는 프로젝트 `public/`에 **이미 있는 실제 파일**을 가리키는 `/images/example.png` 같은 루트 상대 URL만 허용합니다. 참조형 Markdown 링크도 같은 검사 대상입니다. `../`, 역슬래시, 중첩 인코딩, public 밖으로 나가는 symlink는 거부합니다. `/blog/...` 같은 내부 페이지 링크도 실제 public 파일이 아니므로 초기 버전에서는 전체 `https://...` URL로 작성하세요.
- **초기 버전은 링크 수동 변환과 공개 승인된 이미지의 수동 복사가 필요합니다.** vault 첨부파일을 자동 복사하지 않습니다. `public/`는 그 자체로 공개 폴더이므로 비공개 파일을 넣지 마세요. 자동 검사는 민감한 자연어 내용을 판별하지 못하므로 공개 구간과 공개 메타데이터는 반드시 사람이 검토합니다.

## 관리 상태와 복구

- 로컬 `.obsidian-export/manifest.json`에 vault 기준 상대 노트 ID(NFC), 고정 slug, 원본 승인 해시(`sourceHash`), 출력 바이트 해시(`outputHash`)를 저장합니다. 웹 소스 폴더 밖에 있으며 Git에서 제외됩니다. 노트 ID도 민감할 수 있으므로 공개 저장소에 추가하지 마세요. 작업 PC 이동 시 이 상태는 별도로 안전하게 백업·이전해야 합니다.
- 기존 비관리 글, 대소문자·NFC·Astro URL 충돌, 다른 원본의 slug, 동일 원본의 slug 변경을 거부합니다. 노트 이름/경로 변경도 자동 이관하지 않습니다. 직접 편집하거나 삭제한 생성 파일은 덮어쓰지 않습니다. dry-run에도 소유권 검사를 적용합니다.
- 변경하려면 원본에 수정 사항을 반영하고 출력·manifest 상태를 사람이 대조해 복구하세요. manifest를 지워 강제로 덮어쓰는 방식은 지원하지 않습니다. 상태가 없으면 기존 사본은 비관리 글로 간주합니다.
- 단일 로컬 작성자용 잠금을 사용합니다. 다른 편집기에서 생성 파일을 동시에 수정하지 마세요. 쓰기 도중 중단되면 `write.lock` 또는 해시 불일치로 다음 실행이 막힐 수 있습니다. 실행 중 프로세스가 없는지 확인하고 원본·출력·manifest를 대조한 후 잠금/상태를 수동 복구해야 합니다. 두 파일을 한 번에 원자적으로 갱신하는 데이터베이스는 아닙니다.
- 홈페이지·글 목록·정적 글 경로는 공통 `isPublished` 함수로 `draft: true`와 미래 `pubDate`를 빌드 시 제외합니다. 시간 경과만으로 발행되지 않으며 재빌드가 필요합니다. 원본의 승인 취소·삭제도 기존 발행 사본을 자동 삭제하거나 비공개로 바꾸지 않습니다. 발행 취소와 URL 이동은 별도 수동 작업입니다.

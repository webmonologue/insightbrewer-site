ChatGPT 광고를 집행하는 광고주도 클릭 이후의 결과를 확인해야 합니다. 광고를 누른 사람이 웹사이트에서 상품을 구매했는지, 회원가입이나 상담 신청을 마쳤는지 알아야 하기 때문입니다. OpenAI의 전환 측정은 이런 행동을 이벤트로 받아 광고 캠페인과 연결하는 방식입니다.[2]

이때 광고주 서버에서 구매·가입 결과를 OpenAI에 전달하는 API가 **OpenAI Ads Conversions API**입니다. 이 글에서는 무엇을 보내고 어디에 쓰는지, 기존 픽셀이나 다른 광고 플랫폼의 전환 API와 무엇이 다른지, 실제 연동에는 어떤 단계가 필요한지 정리합니다.[1][2]

지원 범위는 **2026년 10월 12일 확인한 공식 문서 기준**입니다. 계정별 기능 활성화 여부와 베타 기능은 실제 연동 전에 다시 확인해야 합니다.[3][9]

## 1. 무엇을 하는 API인가

전환은 광고주가 측정하려는 행동입니다. 쇼핑몰이라면 구매 완료, 서비스라면 가입 완료나 유료 구독 시작, 상담 중심 사업이라면 문의 접수가 될 수 있습니다.[6]

Conversions API는 광고주 서버가 확인한 이런 결과를 OpenAI의 이벤트 수집 서버로 보냅니다. OpenAI에서는 데이터 소스가 이벤트를 받고, 전환 설정이 어떤 이벤트를 전환으로 볼지 정의하며, 캠페인이 그 설정을 사용해 성과를 측정합니다. 전환 최적화 캠페인은 선택한 이벤트를 광고 노출 최적화에도 활용합니다.[2][3]

이 과정에서 이름이 비슷한 세 가지 도구를 구분하면 이해하기 쉽습니다.

| 도구 | 실행 위치와 역할 |
| --- | --- |
| Measurement Pixel | 고객의 브라우저에서 웹사이트 행동을 전송하는 자바스크립트 픽셀 |
| Conversions API | 광고주 서버에서 주문·가입 등 확인된 행동을 전송하는 API |
| Ads API | 데이터 소스·전환 설정·캠페인 등을 생성하고 관리하는 API |

픽셀과 Conversions API는 이벤트를 보내는 통로이고, Ads API는 측정과 광고 운영에 필요한 설정을 관리하는 통로입니다. 서버 이벤트 전송용 Conversions API 키와 광고 관리용 Advertiser API 키도 별개입니다.[2]

예를 들어 쇼핑몰의 구매 완료를 측정한다면, 광고 클릭 → 쇼핑몰 방문 → 결제 완료 → 주문 서버의 구매 이벤트 전송 → OpenAI의 광고 기여도 판정으로 이어집니다. 이는 구조를 설명하기 위한 예시이며, API가 이벤트를 받았다는 사실만으로 해당 주문이 광고 전환으로 인정되는 것은 아닙니다.[1][2]

## 2. 현재 어디까지 지원하나

### 웹 이벤트와 앱 이벤트

웹사이트 행동은 픽셀, Conversions API 또는 두 방식을 함께 사용해 보낼 수 있습니다. 서버만 사용하는 경우에도 데이터 소스를 식별할 Pixel ID는 필요하지만, 브라우저에 픽셀 코드를 설치할 필요는 없습니다.[2]

앱 설치와 실행을 나타내는 `app_installed`, `app_opened`도 지원합니다. 다만 이 두 이벤트는 Conversions API로만 보내며, `action_source`를 `mobile_app`으로 지정해야 합니다. 현재 문서는 기존 웹 데이터 소스의 Pixel ID를 사용하도록 안내하고, 네이티브 모바일 SDK 설치와 모바일 데이터 소스 생성은 지원하지 않는다고 명시합니다. 따라서 ‘앱 이벤트 수신 지원’과 ‘모바일 측정 환경 전체 지원’은 구분해야 합니다.[1][6]

`action_source`에는 `offline`, `physical_store`, `phone_call` 등도 있습니다. 이는 행동의 발생 경로를 표시할 수 있다는 뜻이지, 모든 오프라인 매출을 자동으로 광고와 연결한다는 보장은 아닙니다.[1]

### 표준 이벤트와 커스텀 이벤트

구매·가입·문의처럼 미리 정의된 행동은 표준 이벤트로 보냅니다. 적합한 표준 이벤트가 없는 행동은 `custom`과 별도의 `custom_event_name`으로 정의할 수 있습니다.[2][6]

커스텀 이벤트도 전환 측정에 사용할 수 있지만, 현재 oCPC의 최적화 목표로는 사용할 수 없습니다. oCPC는 전환 가능성이 높은 클릭을 얻도록 광고 노출을 최적화하는 방식으로, 캠페인마다 활성 상태의 표준 전환 설정 하나를 선택합니다.[2][3]

### 측정과 최적화, 과금은 서로 다릅니다

클릭이나 노출을 목표로 하는 캠페인도 전환 설정을 연결해 결과를 측정할 수 있습니다. 전환을 보고서에 표시한다고 해서 캠페인이 자동으로 전환 최적화 방식으로 바뀌지는 않습니다.[2]

표준 캠페인과 상품 피드 캠페인의 oCPC는 현재 오픈 베타로 안내됩니다. 계정에 전환 입찰 기능이 활성화되어 있어야 하며, 캠페인 생성 후 목표나 선택한 전환 이벤트를 바꿀 수 없습니다. **최적화 목표는 전환이지만 과금 기준은 유효 클릭**입니다. 전환이 발생할 때마다 비용을 내는 CPA 과금과는 다릅니다.[3]

전환 데이터 소스와 API 키 생성 역시 계정에 기능이 활성화되어 있어야 합니다. 개발 문서가 공개되어 있다는 이유만으로 모든 광고 계정에서 같은 기능을 사용할 수 있다고 보기는 어렵습니다.[9]

## 3. 기존 전환 측정과 무엇이 다른가

### 브라우저 픽셀과 비교하면: 보내는 위치가 다릅니다

| 비교 항목 | 브라우저 픽셀 | Conversions API |
| --- | --- | --- |
| 이벤트 전송 위치 | 고객 브라우저 | 광고주 서버 |
| 대표적인 연결 지점 | 페이지 조회, 버튼·화면에서 발생한 행동 | 주문 확정, 가입 완료 등 서버가 기록한 결과 |
| OpenAI 클릭 식별자 | 픽셀이 수집 | 광고주가 확보해 서버 이벤트에 전달 |
| 인증 | 브라우저에 API 키를 넣지 않음 | 서버에 보관한 전송용 API 키 사용 |
| 함께 쓸 때 | 같은 전환의 이벤트 ID 공유 | 같은 Pixel ID·이벤트명·이벤트 ID로 중복 제거 |

OpenAI는 픽셀만 사용하는 것보다 Conversions API를 더 신뢰할 수 있는 측정 소스로 안내합니다. 브라우저에서 발생한 신호에만 의존하지 않고 서버에 기록된 결과를 보낼 수 있기 때문입니다. 다만 클릭 식별자 전달과 동의 처리까지 API가 자동으로 해결해 주는 것은 아닙니다.[1][2]

### 다른 광고 플랫폼의 CAPI와 비교하면: 기본 구조는 익숙합니다

서버에서 광고 플랫폼으로 전환 데이터를 보내는 방식 자체는 새로운 개념이 아닙니다. Meta Conversions API도 광고주의 서버·웹 플랫폼·앱·CRM 등의 데이터를 Meta 시스템에 연결해 측정과 최적화에 활용하는 구조입니다.[8]

OpenAI Conversions API의 차이는 이 구조를 **ChatGPT 광고 측정 체계에 연결한다는 점**입니다. 데이터 소스는 OpenAI의 Pixel ID로 지정하고, 클릭 연결에는 OpenAI가 제공한 `oppref`를 전달하며, OpenAI의 이벤트 규격과 전환 설정·캠페인 규칙을 따릅니다.[1][2]

따라서 기존에 다른 매체용 서버 전환 연동이 있더라도 전송 주소만 바꾸면 되지는 않습니다. 주문·회원·CRM에서 행동을 가져오는 부분은 재사용하되, 이벤트명·필드·식별자·중복 제거 규칙은 매체별로 변환하는 구성이 적합합니다. 이는 각 API의 규격 차이를 반영한 연동 설계 제안입니다.[1][8]

## 4. 어떤 데이터를 보내나

### 대표 이벤트

| 측정하려는 행동 | 이벤트명 | `data.type` |
| --- | --- | --- |
| 구매 완료 | `order_created` | `contents` |
| 문의 양식 제출·연락 요청 | `lead_created` | `customer_action` |
| 계정·행사 등록 완료 | `registration_completed` | `customer_action` |
| 유료 구독 시작 | `subscription_created` | `plan_enrollment` |
| 무료 체험 시작 | `trial_started` | `plan_enrollment` |
| 상담·미팅 예약 | `appointment_scheduled` | `customer_action` |
| 결제 절차 시작 | `checkout_started` | `contents` |
| 앱 설치·실행 | `app_installed`, `app_opened` | `customer_action` |

위 표는 공식 이벤트 목록 중 대표적인 항목입니다. `order_created`는 이름만 보면 주문 레코드가 만들어진 시점처럼 보이지만, 공식 정의는 ‘구매 완료’입니다. 내부 시스템에서 주문 생성과 결제 완료가 다르다면 구매 완료 시점에 맞춰 보내야 합니다.[6]

### 이벤트와 식별자 필드

| 필드 | 용도와 주의점 |
| --- | --- |
| `id` | 필수. 이벤트 고유 ID로, 재전송할 때 같은 값을 유지 |
| `type` | 필수. `order_created` 등 행동의 종류 |
| `timestamp_ms` | 필수. 실제 행동 발생 시각을 Unix 밀리초 정수로 전달 |
| `data` | 필수. 이벤트에 맞는 `type`과 금액·상품·플랜 등의 데이터 |
| `action_source`, `source_url` | 행동 발생 경로와 URL. 웹 이벤트는 `source_url` 필수 |
| `oppref` | OpenAI가 제공한 광고 클릭 연결용 식별자. 원문 그대로 전달 |
| `user.obref` | 픽셀의 `__obref` 쿠키에서 얻는 브라우저 참조값. 해시하지 않고 전달 |
| `user.emails_sha256` 등 | 이메일·전화번호·고객 ID 등을 규정대로 정규화한 뒤 SHA-256 해시로 전달하는 선택 필드 |
| `data.amount`, `data.currency` | 이벤트 전체 금액과 통화. 금액이 있으면 통화도 필요 |
| `data.contents` | 상품 ID·수량·단가 등. 해당 데이터 형태가 지원할 때 사용 |

필수 여부와 값의 형식은 이벤트별로 확인해야 합니다. `user`는 선택 항목이며 각 이벤트 안에 넣습니다. `oppref`는 이벤트 최상위 필드이고 `obref`는 `user` 안의 필드라 위치도 다릅니다.[1]

이메일은 앞뒤 공백을 없애고 소문자로 바꾼 뒤 해시합니다. 전화번호는 국가번호를 유지하면서 문서의 정규화 규칙을 적용하고, 외부 고객 ID는 앞뒤 공백만 제거하되 대소문자를 보존합니다. 이 값들은 UTF-8로 인코딩해 SHA-256을 계산한 후 소문자 64자리 16진수 문자열로 보냅니다. 원본 이메일·전화번호·고객 ID를 해당 해시 필드에 넣으면 안 됩니다.[1]

`oppref`와 `obref`, 해시된 고객 식별자는 서로 대체 가능한 이름이 아닙니다. 특히 Conversions API는 `oppref`를 자동 수집하지 않으므로 광고주 측에서 확보하고 구매·가입 이벤트까지 이어서 전달해야 합니다.[1]

## 5. 광고주 시스템과 어떻게 연결하나

직접 연동한다면 다음과 같은 흐름으로 구성할 수 있습니다. 아래는 공식 API 역할을 기준으로 정리한 연동 구조이며, 특정 쇼핑몰이나 CRM에서 구현한 사례는 아닙니다.[1][2]

**이벤트 전송과 광고 설정은 별도 경로입니다.** 위쪽은 실제 행동 데이터를 보내는 경로이고, 아래쪽은 어떤 데이터 소스와 이벤트를 전환으로 측정할지 정한 뒤 캠페인에 연결하는 설정 경로입니다. 이벤트마다 Ads API를 거쳐 전송하는 구조는 아닙니다. 브라우저 픽셀 설치는 선택 사항이며, 이벤트 수신이 광고 기여도 인정을 뜻하지는 않습니다.[1][2]

### ① 데이터 소스와 키를 준비합니다

Ads Manager의 전환 탭에서 Pixel ID와 Conversions API 키를 발급받을 수 있습니다. 승인된 API 파트너는 고객 광고 계정의 Ads API 키와 전환 설정 엔드포인트를 사용해 필요한 리소스를 준비할 수도 있습니다. 브라우저 픽셀과 서버 전송을 함께 사용한다면 같은 데이터 소스를 재사용합니다.[1][2]

여기서 데이터 소스의 `pixel_id`와 `id`를 구분해야 합니다. `pixel_id`는 이벤트 전송에 쓰고, 데이터 소스의 `id`는 전환 설정의 `source_ids`에 넣습니다.[2]

### ② 내부 행동을 OpenAI 이벤트로 변환합니다

주문 시스템의 결제 완료를 `order_created`로, 회원 시스템의 가입 완료를 `registration_completed`로 연결하는 식입니다. 이때 고유 이벤트 ID, 실제 발생 시각, 해당 이벤트에 맞는 `data.type`을 함께 만듭니다.[1][6]

여러 광고 플랫폼에 보내는 구조라면 공통 주문 데이터를 먼저 정리하고 플랫폼별 변환 모듈을 두는 방법을 고려할 수 있습니다. 원본 주문 기록과 전송 기록을 구분해 보관하면 실패 재전송과 중복 확인에도 도움이 됩니다.

### ③ 클릭 식별자를 전환까지 전달합니다

광고 유입에서 제공된 `oppref`를 확보하고, 동의 및 데이터 처리 정책에 맞춰 구매·가입 시점의 서버 이벤트와 연결합니다. 픽셀을 함께 사용하는 경우에는 허용된 범위에서 `__obref` 쿠키 값을 서버로 넘겨 `user.obref`에 넣을 수 있습니다.[1]

서버에서 구매 결과만 읽는 작업과 광고 클릭 식별자를 보존하는 작업은 별개입니다. 전송 API를 붙이기 전에 이 연결 경로부터 설계해야 합니다.[1][2]

### ④ 서버에서 이벤트를 전송합니다

전송 주소는 `POST https://bzr.openai.com/v1/events?pid=<PIXEL-ID>`입니다. Conversions API 키를 Bearer 인증에 사용하며, 요청 본문에는 `events` 배열을 넣습니다. 키는 서버의 비밀 저장소에 보관하고 브라우저 코드·로그·소스 저장소에 노출하지 않습니다.[1][9]

처음에는 요청 최상위에 `validate_only: true`를 넣어 저장 없이 형식을 검사할 수 있습니다. 이 검사는 실제 이벤트 수신이나 광고 기여도 확인과는 다르며, 검증 전용 요청은 이벤트 모니터링에 나타나지 않습니다.[1][2]

### ⑤ 어떤 이벤트를 전환으로 볼지 설정합니다

이벤트를 전송하는 것과 전환 설정을 만드는 것은 별도 단계입니다. 전환 설정에는 이벤트 종류와 데이터 소스 하나를 연결합니다. 현재 Conversion Setup 문서는 클릭 기여 기간인 `attribution_window_days`에 `30`을 사용하도록 안내합니다.[2][9]

### ⑥ 캠페인에 전환 설정을 연결합니다

전환 설정의 ID를 캠페인의 `conversion_event_setting_ids`에 연결합니다. 클릭·노출 캠페인은 측정용으로 연결할 수 있고, oCPC 캠페인은 생성 시 활성 표준 전환 설정 하나를 최적화 목표로 지정합니다.[2][3]

직접 개발하지 않고 파트너를 통해 전송하는 방식도 가능합니다. 공식 문서는 광고주 대신 이벤트를 보내는 파트너가 요청 최상위에 고정된 `integration_source`를 포함하도록 안내합니다. 다만 이 필드가 있다는 사실만으로 사용하는 CRM이나 분석 도구에 완성된 커넥터가 있다고 볼 수는 없습니다. 해당 파트너의 실제 지원 이벤트와 계정 연결 방식을 별도로 확인해야 합니다.[1]

## 6. 구현할 때 놓치기 쉬운 사항

### 중복 이벤트는 나중 데이터로 합쳐지지 않습니다

픽셀과 서버가 같은 구매를 보내면 같은 Pixel ID·이벤트명·이벤트 ID를 사용해야 합니다. 픽셀의 `event_id`와 API의 `id`가 대응하며, 커스텀 이벤트는 이름도 같아야 합니다.[1]

OpenAI는 같은 키로 들어온 첫 이벤트를 사용하고 이후 중복은 무시합니다. 먼저 간 이벤트에 금액이 없더라도 나중 이벤트의 금액을 자동으로 합쳐 주는 구조가 아닙니다. 재시도마다 새 ID를 만들지 않는 것도 중요합니다.[1]

### 해시 처리와 동의 처리는 별개입니다

식별자를 해시했다고 데이터 제공에 필요한 동의나 처리 근거가 생기지는 않습니다. 픽셀 쿠키를 수집·전달할 때는 사이트의 측정 동의 요건을 따라야 하며, 동의가 철회되면 전송을 중단해야 합니다.[1][7]

`opt_out`은 향후 사용자 단위 개인화에서 제외하기 위한 옵션입니다. 현재 OpenAI는 Conversions API로 수집한 데이터를 사용자 단위 개인화에 사용하지 않는다고 명시합니다. 전환 데이터를 올리는 것만으로 리타기팅 오디언스가 만들어진다고 설명하면 안 됩니다.[1]

### 금액과 시각의 단위를 맞춥니다

전환 금액은 통화의 ISO 4217 최소 단위 정수로 보냅니다. 공식 문서의 예를 들면 USD 42.00은 `amount: 4200`, `currency: "USD"`입니다. 상품별 `contents[].amount`는 한 개의 단가이고, 이벤트의 `amount`는 전체 금액입니다.[1][6]

광고 예산·입찰의 `micros`와 전환 금액의 단위는 다릅니다. 기존 캠페인 관리 코드를 재사용할 때 이 두 단위를 혼동하지 않아야 합니다.[2]

`timestamp_ms`는 전송 시각이 아니라 실제 행동 발생 시각입니다. 현재 허용 범위는 과거 7일 이내이며 미래 시각은 10분을 넘길 수 없습니다.[1]

### 배치 실패와 광고 기여도를 따로 확인합니다

한 요청에는 최대 1,000개 이벤트를 보낼 수 있지만, 그중 하나가 유효하지 않으면 배치 전체가 실패합니다. 따라서 형식 검증과 오류 기록을 두고, 실패한 요청을 수정해 재전송할 때도 기존 이벤트 ID를 유지하는 구성이 필요합니다.[1]

웹 전환은 클릭 후 기여도 측정을 지원하며, 계정에 따라 조회 후 기여도도 지원합니다. 조회 후 전환은 적격 광고 노출 이후 1일의 고정 기간을 사용하고 별도 캠페인 지표로 표시됩니다. 클릭과 조회 모두에 해당하면 클릭이 우선합니다.[1]

조회 후 전환은 기본 `Conversions`, CPA, 클릭 후 전환율, 입찰·과금·전환 최적화에 포함되지 않습니다. 따라서 전체 주문 수, API 수신 이벤트 수, 클릭 기여 전환 수, 조회 기여 전환 수를 같은 숫자로 취급하면 안 됩니다.[1]

연동 검증은 형식 검사 → 의도한 데이터 소스의 수신 확인 → 중복 처리 확인 → 전환 설정·캠페인 연결 확인 → 기여도 보고서와 내부 주문 기록 비교 순서로 진행하는 것이 좋습니다. 수신 확인용 모니터링과 기여도 보고용 Insights는 목적이 다릅니다.[2]

## 핵심 요약

- **역할:** 광고주 서버의 구매·가입 결과를 OpenAI에 전달하는 API입니다. 이벤트 전송과 전환 설정·캠페인 관리는 구분합니다.[1][2]
- **지원:** 웹 이벤트와 일부 앱 이벤트를 보낼 수 있으며, 커스텀 이벤트는 측정에 사용할 수 있지만 현재 oCPC 최적화 목표는 표준 이벤트로 제한됩니다.[1][3]
- **차이:** 픽셀과는 전송 위치가 다르고, 다른 플랫폼의 CAPI와는 목적지·식별자·이벤트 규격·캠페인 규칙이 다릅니다.[1][2][8]
- **연동:** 주문·회원·CRM 데이터를 변환하고 클릭 식별자를 연결해 전송한 뒤, 전환 설정과 캠페인까지 연결해야 합니다.[2]
- **주의:** 중복 키와 첫 이벤트 우선 처리, 동의, 금액·시각 단위, 배치 전체 실패 규칙을 확인해야 합니다.[1]
